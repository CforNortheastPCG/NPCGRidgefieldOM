# Full-Bleed Aerial Annotation — Repeatable Process

How we build the edge-to-edge drone-aerial pages with a placeable subject pin,
street labels, route shields, and category-colored place markers (with brand
logos + direction arrows). Repeat this for any OM in the engine.

## Components
- `src/FullBleed.jsx` — the page component. Everything is positioned by **x/y
  percentages of the page** (x = left→right, y = top→bottom). Props:
  - `image` / `position` — the photo and its `object-position`.
  - `pin`     — `{ x, y, label }` golden "Subject Property" teardrop. The label
    auto-aligns left/center/right so it never clips off a page edge.
  - `streets` — `[{ x, y, label, arrow }]` street labels. Rendered like a place
    marker: golden box + an arrow that points at the road (`arrow` in degrees,
    0 = up, clockwise; default 180 = down).
  - `pois`    — `[{ x, y, label, dir?, logo? }]` neighbor/landmark labels
    (`dir`: a literal '↑ ↓ ← →' glyph; `logo`: a path under /public).
  - `shields` — `[{ x, y, route }]` Connecticut route shields (e.g. Route 8).
  - `markers` — `[{ cat, color, name, note, x?, y?, side?, arrow?, logo? }]` the
    category-colored place markers you place/point/delete (see below).
- `src/aerialMarkers.js` — the curated marker list (seeds an unplaced tray).
- `src/nearbyPois.js` / `src/markerLogos.js` — AUTO-GENERATED by the scripts.
- Pages live in `src/App.jsx` in the `pages = [...]` array, inside the Property
  Photography section (before the Financial Analysis divider).

## Step 1 — Read the drone metadata (which way each shot faces)
Source photos are DJI drone shots. Pull GPS + gimbal yaw before labeling:
```bash
python3 - "OM Photos (1)/PHOTO.jpg" <<'PY'
import sys,re
d=open(sys.argv[1],'rb').read(200000)
for k in ['GimbalYawDegree','FlightYawDegree','GimbalPitchDegree',
          'GpsLatitude','GpsLongitude','RelativeAltitude','AbsoluteAltitude']:
    m=re.search(rb'drone-dji:%s="([^"]*)"'%k.encode(),d)
    print(k, m.group(1).decode() if m else '-')
PY
```
- **GimbalYawDegree** = camera heading. 0=N, 90=E, ±180=S, -90=W.
- **GimbalPitchDegree** ≈ -13° = shallow *oblique* (building face + horizon), not
  top-down. The subject sits ahead of the drone along the yaw direction.
- **Gps lat/long** = drone position; compare to the subject to know what's
  ahead/behind/left/right in frame.

Thomaston example: `bleed-1` (photo-7) yaw -9° → looks **North** up South Main St
(downtown ahead); `bleed-2` (photo-3) yaw +159° → over the property looking **South**.

## Step 2 — Size the photos into /public/photos
```bash
sips -Z 2600 "OM Photos (1)/PHOTO.jpg" --out public/photos/bleed-1.jpg
```

## Step 3 — Identify the street + what's up/down it
- Street/route: confirm with a quick web search. Thomaston: South Main St = **US
  Route 6**; Route 8 is the nearby highway (~½ mi east). Transit on the corridor
  is **CTtransit** (Waterbury Division).
- List what's up the street vs down it; anchor with things you're sure of
  (downtown, a highway exit, known anchor tenants).

## Step 4 — Add the page in App.jsx
```jsx
<FullBleed
  image="/photos/bleed-1.jpg"
  pin={{ x: 56, y: 42, label: 'Subject Property' }}
  streets={[{ x: 48, y: 70, label: 'South Main Street · US Route 6', arrow: 180 }]}
  pois={[{ x: 50, y: 22, label: 'Downtown Thomaston', dir: '↓' }]}
  shields={[{ x: 80, y: 48, route: '8' }]}
  markers={AERIAL_MARKERS}   // unplaced tray to start; bake the placed array later
/>,
```
After adding pages, keep `src/Toc.jsx` page numbers in sync (each full-bleed page
shifts everything after it by +1).

## Step 4b — Auto-populate neighbors from Google Places (optional)
```bash
npm run nearby      # scripts/gen-nearby-pois.mjs → src/nearbyPois.js
```
Fetches businesses within ~500 m of the property and **projects** each onto the
oblique aerials using each photo's camera pose, read automatically from its DJI
EXIF/XMP. App.jsx spreads `NEARBY[<id>]` into each page's `pois`. Oblique
projection is approximate → these are starting points you still drag (Step 5).
Needs the **Places API** enabled on `VITE_GOOGLE_MAPS_API_KEY` (`REQUEST_DENIED`
= not enabled). Reuse: edit the `PHOTOS` list (`{ id, file }`) and ensure
`src/amenities.js` exports `PROPERTY { lat, lng }`.

## Step 4c — Auto-fetch brand logos (optional)
```bash
npm run logos       # scripts/gen-marker-logos.mjs → public/logos/markers/ + src/markerLogos.js
```
Matches marker names against a `BRANDS` list (Walgreens, Dunkin', Stop & Shop,
banks, CTtransit for bus stops, …) and writes a name→path map that FullBleed
attaches by name automatically (including onto saved dev placements). Small local
places don't match and stay logo-less by design. No API key needed.

**We use favicons, and that's fine (decided 2026-06-21).** Clearbit's logo API is
dead (HubSpot shut it down), so the script uses each site's favicon
(`google.com/s2/favicons?domain=…&sz=256`). Favicons are the square brand *marks*
(Walgreens "W", Dunkin' cup) — better for a ~15px marker than a wide wordmark.
Sizes vary (CTtransit 16×16, most 64–192px) but render crisp small. If one looks
bad, hand-drop a better PNG at `public/logos/markers/<domain-slug>.png`.

## Step 5 — Place / point / delete in the browser (dev only)
`npm run dev`, then on each page:
- **Drag** any element (pin, street, shields, POIs, markers) to position it.
- Markers stack in a **tray** down the left edge until dragged out (curated list
  in `src/aerialMarkers.js`, categories below).
- **⇄** (gold button above a marker) flips which side the label sits — right →
  bottom → left → top — so it never covers the building.
- **Right-click** a marker (or **scroll** a street label) to spin its **arrow**
  around the anchor toward the road / off-frame target.
- **✕** deletes a marker that isn't visible in that shot (south-of-site places
  belong on the south-looking photo, downtown places on the north-looking one).
- **👁 Render preview / ✎ Edit** (top-left) hides all dev chrome to preview the
  page exactly as it exports; flip back to keep editing.
- Placements **persist across refresh** (localStorage, dev only). **Reset**
  (next to Copy) discards this page's saved placements and reloads from code —
  use it after you bake new values so dev stops showing the old saved ones.

Marker categories/colors (match the Location & Amenities legend, + Transit):
Dining & Coffee #C0392B · Grocery & Pharmacy #1E8449 · Banks, Retail & Employers
#884EA0 · Schools & Civic #2471A3 · Transit #E67E22.

## Step 6 — Bake the placements
1. Click **Copy N markers** (bottom-right, dev only) → copies the kept markers
   with final `x/y`, `side`, `arrow` (and `logo`) to the clipboard.
2. Paste that array into the page's `markers={[...]}` prop in App.jsx. Once a page
   uses an explicit baked array (instead of `AERIAL_MARKERS`), new entries added
   to `aerialMarkers.js` won't auto-appear there — add them to that array too.
3. Pin / street / shield positions: read them off the element after dragging and
   set the props by hand (these aren't in the Copy export).

## Step 7 — Build / export
```bash
npm run build        # sanity check it compiles
npm run pdf          # rasterized PDF export (DSF/QUALITY/BRIGHTEN as usual)
```

## Notes
- Page is **960×742** landscape; the photo is `object-fit: cover` (cropped). If
  the subject sits at a far edge and gets cropped, nudge `position` (object-position)
  on that `<FullBleed>`.
- Everything interactive is gated on `import.meta.env.DEV` — the exported PDF
  shows only the baked, placed elements (no tools, tray, buttons, or drag).
- Photos are intentionally rasterized in the PDF (anti-scrape) — don't switch to
  vector/selectable text.
- The drone shots double as source for the Divider/cover treatment (faded) — see
  `src/Divider.jsx`.
